# 文档地图

这个仓库的文档只分三层：**能干什么（接口）→ 怎么发版（版本与范围）→ 改的时候别踩什么（开发要点）**。
排查过程类的材料（抓包、重放、静态分析、探针）不在公开档，见文末约定。

## 一、阅读顺序

| # | 文档 | 回答什么问题 | 谁该看 |
|---|---|---|---|
| 01 | [接口与请求](01-接口与请求.md) | 四条链路各调什么接口、请求与响应什么形状、错误码怎么判 | 想理解链路、排查「取不到播放地址」 |
| 02 | [版本与维护范围](02-版本与维护范围.md) | 维护哪两套实现、怎么构建、怎么发版、版本号同步在哪、许可口径 | 要改代码、要发版、要写对外文案 |
| 03 | [开发要点](03-开发要点.md) | 协议层 / 签名链 / 界面层 / 跨平台 / 下载器 / 离线回归里的坑 | 动代码之前 |
| 10 | [两源对照与内核统一](10-两源对照与内核统一.md) | 红果与兴趣岛哪些能合并、哪些必须分开、队列与界面怎么收口 | 要重构队列 / 调度 / 清单 |

不用全读：只查接口看 01；只发版看 02 的「构建」「发版」两节；只改界面看 03 第三节。

## 三、维护约定

1. **编号**：公开文档用两位数字前缀，按阅读顺序递增；空号不复用
   （04 及本地留档占用的号段不再启用，公开档从 10 继续）。
2. **新文档**：先在本表登记（一条一行，写清「回答什么问题」），再写正文；没登记的文档等于不存在。
3. **链接纪律**：只链存在的文件；删或改名文档时，同一提交里清干净全仓库引用
   （`git grep <旧文件名>` 扫一遍，README / docs / 代码注释 / 测试都要查）。
4. **逆向内容**：抓包、重放、签名分析、探针、样本一律不写进公开档，也不随提交推送。
   本仓库有一道 `pre-commit` 闸按本地词表拦截，误伤时用 `HGVD_REV_SKIP=1` 放行。
5. **时效**：涉及「现在还能不能用」的结论必须标日期，并写清复核方式；不写「理论上」。
