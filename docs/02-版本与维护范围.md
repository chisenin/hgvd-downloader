# 02 · 版本与维护范围

---

## 一、只维护两套实现

| 角色 | 实现 | 位置 | 形态 |
|---|---|---|---|
| **发行版**（日常使用） | **C# + Avalonia 11** | `hgvd-avalonia/` | **自包含目录版 + zip**（约 53 MB，.NET 运行时与 ffmpeg/ffprobe 全部内置，目标机零安装）；另附单文件 exe 备用 |
| **想法验证**（改逻辑用） | **Python** | `hgvd/` | 命令行 + 本地网页界面，依赖极少 |
| 共享核心 | C# `Hgvd.Core` | `hgvd-csharp/src/Hgvd.Core/` | 签名链 / 下载器 / 配置目录 / 设备身份 |
| 兴趣岛下载内核 | C# `Hgvd.Xqd` | `hgvd-csharp/src/Hgvd.Xqd/` | HLS 清单 / 分片下载 / ffmpeg 合成 / 直链音频（**不含** ADB 自动化） |
| 离线回归 | C# `Hgvd.Tests` | `hgvd-csharp/src/Hgvd.Tests/` | 118 项 |

> ★ 两套实现**共用同一套核心**与协议理解，登录态 / 设备档案 / 下载历史可以直接互换。
> 协议细节见 [`01-接口与请求.md`](01-接口与请求.md)。

**为什么这样分工**：Python 版改逻辑快（改完跑一遍就知道对不对），
适合验证接口与算法；Avalonia 版做成交付形态，适合日常使用。
核心修复只改一处（`Hgvd.Core`），两边同时受益。

## 二、构建

### Python 版

```bash
pip install -r requirements.txt
python -m hgvd --help
```

### C# + Avalonia 发行版

```bash
cd hgvd-avalonia
./build.sh            # 或 Windows 下 build.cmd
```

产物（**B 案：目录版 + zip 为主推**）：

| 形态 | 路径 | 体积 |
|---|---|---|
| **目录版压缩包**（推荐） | `hgvd-avalonia/dist/hgvd-downloader-v1.3.0-win-x64.zip` | 约 53 MB |
| 目录版（未压缩） | `hgvd-avalonia/pkg/hgvd-downloader-v1.3.0/` | 约 77 MB / 96 个文件 |
| 单文件（备用） | `hgvd-avalonia/dist/hgvd-downloader-v1.3.0.exe` | 约 58 MB |

> ★ 为什么主推 zip：单文件把 ffmpeg 内嵌后是"假单文件"（首次运行仍要解压到
> `%LOCALAPPDATA%`，磁盘翻倍），而且"exe 解出 exe"容易触发杀软启发式。
> zip 版本启动更快、ffmpeg 可替换、出问题能直接看目录里有什么。
> 选型讨论见 `03-开发要点.md` §3.6。

构建分五步，发版再加一步验证：

| 步 | 做什么 |
|---|---|
| 1 | `prepare-ffmpeg.ps1` —— 从 npmmirror 取 `@ffmpeg-installer/win32-x64` 与 `@ffprobe-installer/win32-x64`，解出 exe 压成 `..\.cache\ffmpeg\*.exe.gz`（已存在则跳过） |
| 2 | `dotnet restore -p:Configuration=Release --configfile NuGet.config -r win-x64`（★ 这个 `-p:Configuration=Release` 不能省，否则 ILLink 拉不到、裁剪静默失效，见 `03-开发要点.md` §3.6） |
| 3 | `dotnet publish ... -p:PublishSingleFile=false -o pkg\<APP>\` —— 目录版（`.exe.gz` 作为 `EmbeddedResource` 嵌入主程序集） |
| 4 | `python tools/pack_zip.py` 打成 `dist\*-win-x64.zip`（顶层保留文件夹名、放入 `README.txt`） |
| 5 | `dotnet publish ... -o dist\` —— 单文件 exe（备用形态） |
| 6 | **发版必做**：`build.cmd verify` / `build.sh verify` —— 构建后再跑 `--uitest`（界面自检）+ `--batchtest 1`（真下一集），**验的是目录版**。`tools/publish_release.sh` 会检查这两份日志，不过就拒绝打标签。见 `03-开发要点.md` §6.1 |

发布配置（`Directory.Build.props` + `Hgvd.Avalonia.csproj`）：
自包含 / 单文件 / 压缩 / `PublishTrimmed` + `TrimMode=partial`，
并保根 `Avalonia.*` 与两个自有程序集（反射绑定的前提，见 `03-开发要点.md` §3.6）。

运行时由 `FfmpegRuntime.Ensure()` 在界面起来之前把内置资源流式解压到
`%LOCALAPPDATA%\hgvd-downloader\runtime\ffmpeg-<程序集版本>\`，路径交给
`Hgvd.Core.ToolPaths`；目录已存在就直接复用，所以只有首次启动慢几秒。
`Hgvd.Core` 里所有 `ProcessStartInfo("ffmpeg"/"ffprobe")` 都走 `ToolPaths`，找不到内置的就回退 PATH。

> ★ `Hgvd.Core` 在 `hgvd-csharp/` 下，而 `NuGet.config` 在 `hgvd-avalonia/` 下 ——
> NuGet 配置是**按项目目录向上查找**的，所以发布前必须显式
> `dotnet restore --configfile NuGet.config -r win-x64`（构建脚本已经带上了）。
> 少了这一步会报 `NU1100：无法解析 Microsoft.NETCore.App.Runtime.win-x64`。

## 三、离线回归

两套回归都**不发网络请求**，几秒出结果，用来挡住签名链 / 请求头 / 播放协议 / 界面回归的破坏。

```bash
# Python：107 项（I 组 17 项守 preload 协议与「不校验签名头」的结论）
python -m tests.run

# C#：118 项（签名黄金向量 22 + 完整请求头 12 + x-argus/x-ladon 字节级 6
#         + 发行版界面 13 + 命名规则 9 + MuMu 安装位置发现 7 + 设备档案 3 + DRM 6
#         + 兴趣岛内核 40：链接解析/清单/命名/队列）
dotnet restore hgvd-csharp/src/Hgvd.Tests/Hgvd.Tests.csproj --configfile .github/nuget.ci.config
dotnet build   hgvd-csharp/src/Hgvd.Tests/Hgvd.Tests.csproj -c Debug --no-restore
./hgvd-csharp/src/Hgvd.Tests/bin/Debug/net8.0-windows/Hgvd.Tests.exe
```

★ **界面回归必须在发行版上做**：`EpisodeRow` 的属性通知测试针对的是 Avalonia 的
`EpisodeRow`（`hgvd-csharp/src/Hgvd.Tests/AvaloniaEpisodeRowTests.cs`）。
踩过的坑是「改了值但界面不刷新」—— 绑定的是**计算属性**（`SizeText` / `SpeedText`），
setter 只通知自己就不会触发重新求值。这类 bug **必须断言通知事件的名字**，
只断言最终值测不出来（值本身是对的）。

## 四、GitHub Actions

| 工作流 | 触发条件 | 做什么 |
|---|---|---|
| `.github/workflows/ci.yml` | push / PR 到 `main` | C# 118 项 + Python 107 项离线回归，并验证能 publish 出单文件 exe |
| `.github/workflows/release.yml` | 推 `v*` 标签 | 离线回归 → 按标签版本 publish → 核对产物版本 → 创建 Release 并上传 exe |

CI 用专用的 `.github/nuget.ci.config`（只走 nuget.org）——
仓库里 `hgvd-avalonia/NuGet.config` 把 `nuget.azure.cn` 排在第一位（国内快），
但托管 runner 在海外。

★ **CI 上不能跑 `--uitest`**：它需要真实登录态与收藏夹。
★ **Windows runner 的 stdout 是管道**，Python 会取 ANSI 代码页（cp1252），
打印中文会 `UnicodeEncodeError` ⇒ 工作流里设了 `PYTHONUTF8=1`，
`tests/run.py` / `hgvd/cli.py` 也会把 stdout 重配为 UTF-8。

## 五、发版

```bash
bash tools/publish_release.sh v1.3.0
```

脚本会：同步 `main` → 打带注释的标签 → 推 `main` 与标签 → Release 工作流被触发。
手工等价写法：

```bash
git tag -a v1.3.0 -m "发布 v1.3.0"
git push origin main v1.3.0
```

★ **标签版本号 = 产物版本号 = 界面显示的版本号**（单一来源）。
工作流会核对 exe 的 `FileVersion` 与标签是否一致，不一致直接失败。

发布物：<https://github.com/chisenin/hgvd-downloader/releases>

## 六、命名约定

- 成品 exe 统一叫 **`hgvd-downloader-vX.Y.Z.exe`**。
- 版本号唯一来源 = `build.cmd` / `build.sh` 里的 `VER`
  （等价于 csproj 的 `PkgVersion`）。
- 目录前缀统一 `hgvd-`。
