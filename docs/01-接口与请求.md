# 01 · 接口与请求

> [文档地图](README.md) ｜ 本篇 **01 接口与请求** ｜ 下一篇 [02 版本与维护范围](02-版本与维护范围.md)

本项目的技术核心：**怎么拿到完整正片的播放地址**。
两套实现（Python / C#）共用同一套协议理解。

> ★ 2026-11-21 04:10 起，播放链路**强校验签名头**（判据与实测记录属维护者本地留档，
> 不随本仓库发布）。
> ⚠ 本文只写「形状」，**「现在能不能用」必须真机复核** —— 那条判据被改过两次，别照抄旧结论。
> 踩过的坑在 §八。

## 一、四条链路

| 环节 | 接口 | 签名 | 登录 | 说明 |
|---|---|---|---|---|
| 收藏夹 | `GET /reading/bookapi/bookshelf/video/list/v` | ✗ | ✓ | 不带 cookie 返回空列表 |
| 剧目 + 全集列表 | 网页版 `/detail?series_id=<id>` 的 SSR | ✗ | ✗ | `_ROUTER_DATA` 里带全部 `vid` |
| 单集时长 / 分辨率 | 网页版 `/player/<sid>/<vid>` 的 SSR | ✗ | ✗ | 只有前 5 集有 SEO 元信息 |
| **完整正片** | `POST /novel/player/multi_video_model/preload/v1` | **✓ 强校验** | 可选 | 门槛 = `X-Helios`+`X-Medusa`（绑定 query+body **字节**）**和** body 形状 |

### 网页版能做什么、不能做什么

`/detail` 页内嵌 `_ROUTER_DATA`，免签名就能拿到全部分集 ID、单集时长、分辨率。

播放页里也有免签名直链 `https://hongguoduanju.com/video/public/<vid>/360p.mp4` ——
**能下载，但只有 10 秒**（SEO 预览片段），不是正片。

⇒ 完整正片必须走 App 网关的 `preload` 接口，与网页版无关。

## 二、播放请求

完整样例、判据实验、抓包方法属维护者本地留档（不随本仓库发布），这里只列要点：

```
POST /novel/player/multi_video_model/preload/v1?<设备参数>
Content-Type: application/json; charset=utf-8
Content-Encoding: gzip
body = gzip({"biz_param":{…,"video_platform":1024},
             "dr_scene":"preload",
             "mixed_video_id_map":{"<内容类型>":["<vid>"]}})
```

### `mixed_video_id_map` 的键 = 内容类型

| 键 | 适用 | 用错的表现 |
|---|---|---|
| `1004` | 视频流 / 短剧 | 教学集 → `code=101000` |
| `1001` / `1000` | 教学合集分集 | 视频流 → `code=0` 但 `video_list` 为空 |

⇒ 客户端按 `1004 → 1001 → 1000` 依次试，取第一个能解析出 `video_list` 的。

### 响应

`data` 按 vid 分组，`video_model` 是**嵌套 JSON 字符串**：

```
data[vid].video_model           ← JSON 字符串
  .video_list[]
    .main_url / .backup_url     ← CDN 直链
    .video_meta.definition      ← 360p / 720p / 1080p
    .video_meta.vtype           ← mp4
    .encrypt_info.spade_a       ← CENC 密钥材料（加密时才有）
```

`main_url` 实测 `Range: bytes=0-1023` → `206` + `ftyp`，可直接下载。

### 两套实现

| 语言 | 位置 |
|---|---|
| Python | `hgvd/api/playback.py` |
| C# | `hgvd-csharp/src/Hgvd.Core/Api/SignedClient.cs` |

## 三、签名链（播放链路**必须**带，但当前算不出来）

实现仍在仓库里（Python `hgvd/sign/`、C# `Hgvd.Core/Sign/`），
但 **2026-11-21 起服务端在所有播放端点、所有网关上强校验 `X-Helios` + `X-Medusa`**，
现有实现生成的值**不被接受**（为什么、差在哪，属维护者本地留档）
⇒ **播放链路目前不可用**（取直链的兜底路径已于 2026-11-22 裁掉，见 README「关于抓流/自动抓剧」）。

保留这套实现还有三条理由：

1. 其它端点（配置、上报等）仍会带 `x-gorgon` / `x-helios` / `x-ss-stub`，保持与 App 一致；
2. 历史黄金向量（`hgvd-csharp/tools/golden_argus.json`）仍是**移植正确性**的护栏 ——
   但它**不再是「能不能下载」的判据**；
3. 保留它是为了让请求头形态与 App 保持一致，便于后续对照（对照材料属维护者本地留档）。

### 移植密码学时的两个隐形杀手（历史坑，仍然有效）

- **`int` 溢出**：C# 的 `int` 是 32 位有符号，`ts << 1` 在时间戳较大时溢出成负数
  ⇒ 签名与预期完全无关。Python 无此问题 ⇒「Python 通、C# 不通」时优先查溢出。
- **PKCS#7 填充值**：填充字节写错不会报错，但解出来不是合法 JSON
  ⇒ 表现与「服务端丢弃请求」一模一样 —— 这是历史上多次误判的入口。

### 黄金向量别再放桩值

曾经 `golden_headers.json` 里的 `x-argus` 只是 4 字节时间戳桩，
真签名从来没被逐字节比对过 ⇒ 移植 bug 长期潜伏。
⇒ 黄金向量必须是**真实字节级样本**。

## 四、设备身份

请求 query 需要设备参数，且要与登录态**同源**（同一次 `login` 落盘的档案）：

| 字段 | 来源 |
|---|---|
| `sessionid` / `sid_tt` | `shared_prefs/cookieStore.xml` |
| `install_id` | `shared_prefs/cookieStore.xml` |
| `odin_tt` | `shared_prefs/cookieStore.xml` |
| `X-Tt-Token` | `shared_prefs/token_shared_preference.xml` |
| `device_id` | `shared_prefs/applog_stats.xml` |

★ 同一账号在不同模拟器实例上 `sessionid` 可能相同，但 `device_id` / `install_id` 不同
⇒ 登录态与设备档案必须来自**同一个实例**。

★ 播放接口本身匿名也能通，但带上与登录态同源的设备参数更接近真实客户端。

## 五、错误码与「空 body」的判据

| 现象 | 含义 | 处理 |
|---|---|---|
| JSON `code=0` 且有 `video_list` | 成功 | — |
| `code=101000` | **内容类型 key 用错**（教学 1000/1001、视频流 1004） | **换 key**，不要重试同一个 |
| `code=100001` | 参数错误（典型：body 缺 `biz_param`） | 补 body 字段 |
| **零字节 body** | 端点已停用 / 网关丢弃 / **签名无效** | **先怀疑路径变了**，再查签名（05 §1.3）；不要退避等待 |
| `502 / 404` 且非 JSON | 路径或网关变更 | 核对路径与网关列表 |
| 超时 / 连接失败 | 网络问题 | 重试有意义 |

⇒ **绝不**把空 body 写成「服务端限流」：真正的限流必然随间隔恢复，
本项目 7 轮退避 19 分钟没恢复、隔几天第一发照旧空。

⇒ 「拿到 JSON」只能证明**这个端点不验签**，不能证明签名有效
（`album_detail` / `multi_video_detail` 完全匿名也返回 `code=0`）。

### 网关

播放接口有多个候选网关（`api5-normal-sinfonlineb` / `api5-normal-lf` / `reading.snssdk`），
实现里依次尝试；单节点抽风不影响下载。
`HGVD_PLAYBACK_HOST` 可覆盖顺序（逗号分隔），用于验证故障转移分支真的被执行过。

## 六、三类内容

| 类型 | `book_type` | 分集来源 | 播放 key | 编码 | 状态 |
|---|---|---|---|---|---|
| **教学合集** | 3 | `album_detail` | `1001` / `1000` | 标准 HEVC + AAC，不加密 | ✅ 可用 |
| **短剧** | 2 | `multi_video_detail/preload` | `1004` | bytevc2，加密 + SPS/PPS 被抹 | ⚠️ 能下载能解密，但 ffmpeg 解不出画面 |
| 图书 / 听书 | 3（部分） | — | — | — | ❌ 服务端确实没有视频 |

★ `codec_type=bytevc1` 只是**元数据标签**，实际文件就是标准 HEVC。

## 七、备用路径：提取 App 缓存

红果 App 播放过的视频会缓存在本地。提取它**不经过播放接口** ——
服务端出问题时这是唯一还能出片的路。

```bash
python -m hgvd cache --list
python -m hgvd cache --out ./videos
```

实现：`hgvd/auth/cache_extract.py` / `Hgvd.Core/Auth/CacheExtract.cs`。

## 八、协议实现里的坑

| 坑 | 结论 |
|---|---|
| 网页版详情页路径 | 是 `/detail?series_id=<id>`（不是 `/series/<id>`），正则要**非贪婪** |
| `Content-Type: application/json` + `Content-Encoding: gzip` | body 必须真的 gzip，两件头都要有；服务端按头解 |
| `video_model` 是字符串 | 服务端返回的是**嵌套 JSON 字符串**，要二次 parse |
| `video_list` 也可能是字符串 | 解析前先判 `ValueKind`（C#）/ `isinstance(str)`（Python） |
| 备用直链 `backup_url` | 解析了但下载器没用过 —— 主链可用时没必要 |
| 收藏接口「不带 cookie」与「带假 cookie」 | 不带 cookie 返回空列表，别误判成「接口挂了」 |
| `sessionid` 判据 | `sessionid` 或 `sessionid_ss` **任一非空**即算登录成功 |
